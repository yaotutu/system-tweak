# 同步配置规范

本目录保存需要在 Omarchy 电脑之间复现的“目标状态文档”，不是变更流水账。

## 设计原则

1. 一个主题一个文件，不要把所有设置写进一个大文档。
2. `INDEX.md` 只做导航，不承载细节。
3. 所有主题都位于 `sync/topics/` 下，不再按通用/平台分双层目录。
4. 同一功能的后续变化更新原文件，不新增重复主题。
5. 单个主题文件建议不超过 150 行；超过时按用户可感知的行为继续拆分。
6. 涉及硬件差异的内容写“先检测再适配”，不直接复制本机值。
7. 敏感信息不入库。
8. 不创建额外的同步 changelog；文件历史由 Git commit 记录。

## 主题文件格式

```markdown
# <主题名>

- **状态**: <Stable / Experimental / Draft>
- **适用范围**: Omarchy
- **最后验证**: <YYYY-MM-DD>

## 目标状态
- <用户最终希望得到的行为>

## 关键方案
- <涉及文件、软件包、插件或命令>

## 硬件/环境差异
- <需要检测的内容，以及不能直接照抄的原因>

## 经验教训
- <反复调试后才发现的关键原因和正确思路>

## 验证
- <完成后应检查什么，以及期望结果>
```

## 维护规则

1. 新增主题前先检查 `INDEX.md`，确认没有已有主题可以承载。
2. 新增主题后必须同步更新 `INDEX.md`。
3. 修改主题前先对比本机 `logs/`、系统实际状态和 `sync/`。
4. 用户明确同意后才能新增、修改或删除主题。
5. 如果一个主题超过 150 行，优先拆分为更小的主题文件。
6. 被后续方案取代的旧做法只保留在“经验教训”，不保留为目标状态。
