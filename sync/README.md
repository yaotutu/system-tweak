# 同步配置规范

本目录描述 Omarchy 电脑之间需要复现的最终目标状态。它是“目标数据”，不是变更流水账；如何写入或应用由 `skills/` 中的流程文档负责。

## 原则

1. `sync/topics/` 采用一个主题一个文件的结构。
2. 主题按用户可感知的行为划分，不按配置文件、软件包或插件划分。
3. 同一功能的后续变化更新原主题文件，不新增重复主题。
4. `INDEX.md` 只做导航，不承载细节。
5. 当前只有 Omarchy 一个平台；若未来出现第二个平台，再重新设计目录层级。
6. 单个主题建议不超过 150 行；超过时按用户可感知的行为继续拆分。
7. 硬件相关意图必须描述检测和适配方法，不直接复制某台机器的硬件值。
8. 敏感信息不入库。
9. 不创建同步 changelog；文档历史由 Git 提交记录。

## 状态语义

- `Stable`
  - 目标状态和实现方案已稳定，可作为默认复现目标。
  - 只表示设计意图稳定，不代表每台机器都已经成功应用。
- `Experimental`
  - 方案仍在试验；未经用户明确要求，不应应用到其他电脑。
- `Draft`
  - 目标尚未最终确定，只用于记录想法。

`最后验证` 表示最近一次在任意一台目标机器上验证通过的日期。

## 主题文件格式

```markdown
# <主题名>

- **状态**: <Stable / Experimental / Draft>
- **适用范围**: Omarchy
- **最后验证**: <YYYY-MM-DD>

## 目标状态
- <用户最终希望得到的行为>

## 关键方案
- <涉及文件、软件包、插件或命令>

## 硬件/环境差异
- <需要检测的内容，以及不能直接照抄的原因>

## 经验教训
- <反复调试后才发现的关键原因和正确思路>

## 验证
- <完成后应检查什么，以及期望结果>
```

## 硬件适配要求

1. 同步意图，不盲目同步具体机器的硬件值。
2. 主题文件必须说明应该检测什么，以及如何根据检测结果适配。
3. 显示器、GPU、声卡、网络接口、外接键盘等值不能直接照抄。
4. 无法可靠适配时，不得标记为 `Stable`。
