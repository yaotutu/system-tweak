# system-tweak

这是一个面向 Linux / Omarchy 的系统配置知识库。

它不自动同步电脑状态，不自动执行配置，也不维护“哪些变更已经应用”的台账。`configurations/` 只是参考方案：Agent 先分析当前电脑和用户目标，说明可选择的实施范围；用户确认后才操作。

## 内容分类

```text
logs/            本机真实变更历史，不同步
backups/         本机修改前备份，不同步
configurations/  按软件或功能分类的参考方案，同步
knowledge/       根因、经验、坑和排错知识，同步
```

## 使用方式

### 查找可实现的功能

浏览 [configurations/INDEX.md](configurations/INDEX.md)，例如：

```text
请读取 configurations/fcitx5/rime-chinese-input.md。
先只读检查当前电脑，告诉我目前状态、可以实现到哪些程度、
每个选项会修改和保留什么，并给出建议。等我确认后再操作。
```

配置文档不是目标状态或自动脚本。标准流程分两步：

1. **只读分析**
   - 检查当前包版本、服务、配置、行为和已有偏好；
   - 比较当前状态、参考方案和用户目标；
   - 提供一个或多个可选范围；
   - 说明每个选项会修改、保留、不处理什么，以及风险和验证方式；
   - 等待用户明确选择。
2. **确认后实施**
   - 只实现用户选择的范围；
   - 修改前备份；
   - 最小化修改；
   - 执行命令验证和真实人工测试；
   - 将本机实际修改写入 `logs/YYYY-MM.md`。

### 查询问题和经验

浏览 [knowledge/INDEX.md](knowledge/INDEX.md)。这些文档解释根因、正确思路和环境差异，不直接触发修改。

## 配置参考文档标准

每份 `configurations/` 文档应包含：

- 参考目标和已验证环境；
- 修改前只读检查；
- 可以独立选择的实施范围；
- 每个范围会修改、保留和不处理什么；
- 需要用户确认的决策；
- 用户确认后可复用的步骤和关键片段；
- 备份建议；
- 自动和人工验证；
- 回滚参考；
- 相关经验链接。

文档不能包含真实配置文件的整份副本、密码、Token、密钥、私人数据，或假设其他电脑拥有相同硬件值。文档不能宣称“应完整恢复本文状态”；最终目标只能由 Agent 分析后提出，并由用户确认。

## 本机历史

`logs/` 记录这台电脑实际发生的修改，按时间排列，不进入 Git：

```markdown
## 2026-09-25 10:00 · 一句话摘要

- **Category**: configuration
- **Details**: 修改内容和备份位置
- **Verification**: 验证结果
- **Status**: ✅ complete
```

`backups/` 同样只属于当前电脑。

## Git 边界

同步：

```text
AGENTS.md
README.md
configurations/
knowledge/
```

永不提交：

```text
logs/
backups/
真实系统配置
密钥、账号和私人数据
```

修改共享文档后应 commit 并 push。Push 失败时只能说“本地已提交、尚未同步”。
